01 · The problem

Shoulder surfing needs no tools, only a clear view.

Shoulder surfing is when someone stands close to a kiosk and watches a customer type their PIN. It needs no hacking tools or skimming hardware, and it's invisible: privacy screens are passive, nothing flags when someone is peeking, and victims usually find out days later when unauthorized transactions appear.

The risk is highest at agent-banking points, where shopkeepers process transactions in open stalls with people standing close behind the customer.

02 · What it does

Every frame becomes one of two answers.

Perimeter watches the area around a kiosk through a webcam and classifies every frame as one of two classes.

positive

One person in frame: safe

  • Green border around the feed
  • Readout shows the confidence score
negative

Multiple people in frame: possible shoulder surfing

  • Red border and an alert banner
  • A timestamped entry in the event log
Privacy by design. No image or video frame is uploaded, stored, or sent anywhere. That protects customer privacy and keeps it working on unreliable internet.
03 · How it works

From webcam to verdict, inside one browser tab.

STAGE 1

Capture

The browser reads webcam frames with getUserMedia.

→ live video frame
STAGE 2

Pre-process

Each frame is drawn onto a hidden 96×96 canvas and packed into the format the model expects.

→ 9,216 RGB features
STAGE 3

Classify

The Edge Impulse model, compiled to WebAssembly, runs right in the tab.

→ positive / negative + confidence
STAGE 4

Alert

If negative scores above the threshold (50%, 60% or 75%), the interface turns red and logs the event.

→ max 1 log entry / 2 s
Webcam → resize frame to 96×96 → pack RGB pixels into features
       → Edge Impulse model (WebAssembly) → positive / negative + confidence
       → alert if "negative" confidence ≥ threshold
rgb

Each pixel becomes a single number: (r << 16) + (g << 8) + b. The input size and class labels are read from the model at load time, so a retrained model can be dropped in without any code changes.

04 · How I built it

From a fintech question to a working prototype.

Defined the problem

I started from "where can low-cost edge AI close a real gap in fintech?" and chose shoulder surfing at kiosks because it's common, cheap for attackers, and currently undetected.

Framed it as a classification task

Instead of detecting and counting faces, I trained a simple whole-frame classifier: one person vs multiple people. It's lightweight, fast, and fits the use case.

Built the dataset in Edge Impulse

I labeled images as positive (single person) and negative (two or more people), then split them into training and test sets.

Trained and tested the model

I checked results in Edge Impulse's Live Classification view, where example images scored:

positive 0.99negative 0.92

Exported for the browser

I exported the model as WebAssembly (browser, SIMD), which produces edge-impulse-standalone.js and .wasm.

Built the web app

Using Claude as an AI coding assistant, I translated my concept and functional requirements into a working web application. I guided its development by specifying the webcam capture, feature extraction and inference, and designed the security-console interface with live readouts, debugging panels and event logging.

Deployed and recorded a demo

I hosted it on Netlify to get an HTTPS link for camera access, then recorded a screen demo: one person shows positive, and a second person stepping in triggers negative.

Iterated on the model

I retrained and re-exported several times (deploy versions 3 to 6). Because the app reads its settings from the model, each new export only needed the .wasm file swapped in.

05 · Challenges and what I learned

The model is only as good as its data.

DATASET EXPANSION

Improving accuracy by expanding the dataset

My initial model could identify groups of more than two people as negative, but struggled to recognize exactly two people.

BEFOREGroups of 3+ flagged. Exactly two people often missed.
AFTERMore two-person examples added, model retrained, web app rebuilt.

This taught me the importance of dataset diversity, identifying model limitations, and iteratively improving machine-learning systems based on their performance.

WRONG EXPORT

C++ doesn't run in a browser

My first download was the C++ library for microcontrollers, which can't run in a browser. The right target was the WebAssembly export.

BROWSER RULES

MIME types and HTTPS

.wasm files must be served over HTTP with the right MIME type, and the camera needs HTTPS once the app is off localhost.

LESSON

Build in debugging from day one

Visible raw output and an event log cut the time it took to find each problem.

06 · Limitations and future work

An honest prototype, with a clear path forward.

Limitations

  • It's a whole-frame classifier. It can't tell how close a second person is, whether they're looking at the screen, or whether they're a legitimate bystander far away.
  • Accuracy depends on the training data matching the real camera angle, distance and lighting at the kiosk. I tested with a laptop webcam, not a kiosk-mounted camera.
  • This is a working prototype, not a production security product.

Future work

  • Train on more data captured at real kiosk camera angles and heights.
  • Add a distance or proximity signal so far-away bystanders don't trigger alerts.
  • Trigger a response beyond a visual alert, such as a privacy shutter or a prompt to cover the PIN pad.
  • Port it to a Raspberry Pi or other low-cost hardware for deployment at agent points.
